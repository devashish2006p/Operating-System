## Process Hierarchy

Process Hierarchy means the **parent-child relationship structure** of processes, where one process creates another, which becomes the child process.  

---

### Parent Process
A **parent process** is the one that creates a new process. It stores the child’s PID, receives the child’s exit status, and can send signals to the child.

---

### Child Process
A **child process** is created by a parent. It has its own unique PID, and stores the parent’s PID (PPID).

---

### Process Creation & Hierarchy Formation
1. Parent process is running  
2. Parent calls `fork()`  
3. OS creates child process  
4. Child gets new PID and PPID  
5. Hierarchy updated in kernel tables  

> All information is stored in the PCB.

---

### Resource Inheritance
1. **Open files & file descriptors** – Child inherits parent’s open files; can read/write same files.  
2. **Environment Variables** – PATH, HOME, USER, etc. inherited so child works in same environment.  
3. **Current Working Directory** – Child starts in same folder as parent for consistent file paths.  
4. **File Permission Mask** – Default file creation permissions inherited by child.  
5. **Signal Handlers/Disposition** – Child inherits parent’s signal handling behavior.  
6. **Process Credentials (UID, GID)** – Same user/group IDs for access control.  
7. **Resource Limits** – CPU time, memory usage, file size limits inherited.  
8. **Shared memory/mapped resources** – Memory-mapped files and shared objects accessible to child for fast data exchange and code reuse.

---

### Process Termination & Hierarchy Effects

**Process Termination** means a process finishes execution and OS frees its resources. OS needs to know which process terminated to maintain system stability.

---

### Types of Process Termination
1. **Normal/Voluntary Termination** – Process finishes on its own. OS generates exit code, frees resources, notifies parent.  
2. **Abnormal/Forced Termination** – Terminated by user or OS action. OS immediately frees resources and notifies parent.  
3. **Parent Termination** – If parent terminates while child is alive, child becomes an orphan. OS assigns `init`/`systemd` as new parent.

---

### Process Hierarchy Effects
1. **Child termination** – Exit code generated, PCB kept until parent reads status. If parent doesn’t `wait()`, child remains as **zombie**.  
2. **Parent termination** – Child becomes an **orphan** if parent dies while child is alive.  
3. **Multiple children** – Parent may have multiple children. If parent dies, all children adopted by `init`. If children die and parent alive, zombies created.  
4. **Zombie Process** – Child terminated, parent hasn’t read exit status; PCB entry still exists.  
5. **Orphan Process** – Child alive, parent terminated; child called orphan process.
