## Thread Concepts

A **Thread** is a lightweight execution unit that exists within a process. It shares the process resources but can execute independently on the CPU, allowing the process to perform tasks in parallel.

---

### Components of a Thread
1. **Thread ID (TID)** – Unique identity of the thread. OS uses this to recognize and manage the thread.  
2. **Program Counter (PC)** – Indicates which instruction the thread is currently executing. Saved/restored during context switch.  
3. **Register Set** – CPU registers holding the thread’s current execution state. Each thread has its own register context.  
4. **Stack** – Stores function calls, local variables, return addresses. Each thread has its own separate stack.

---

### TCB (Thread Control Block)
A **Thread Control Block** is a kernel data structure that stores all execution-related information for a thread.

**Contents of TCB:**
1. **Thread ID (TID)** – Unique identity of the thread.  
2. **Thread State** – Ready / Running / Blocked / Terminated  
3. **Program Counter (PC)** – Next instruction address for the thread.  
4. **CPU Register Set** – Registers needed for thread execution.  
5. **Stack Pointer / Stack Info** – Start and end of thread’s stack.  
6. **Scheduling Information** – Priority, time-slice, scheduling class.  
7. **Pointer to Parent Process (PCB link)** – Shows which process the thread belongs to.

---

### Single-Threaded vs Multi-Threaded Process
- **Single-Threaded Process** – Contains only one thread that executes all tasks sequentially.  
- **Multi-Threaded Process** – Contains multiple threads within a single process that execute tasks in parallel or concurrently.

---

### Types of Threads
**Threads ko 2 bases par divide kiya jaa shakta hai ek Management Base par aur dushra location ka basis par.**
- **1. Management Base**
  - **1) User Level Thread (ULT)** : User level thread ek aisa thread hota hai jiska pura control application ya programming library karti hai aur os drectly us thread ko alag sa nahi dekhta, isiliye application apne ander bahut jaldi aur kam cost ma multiple chote execution workers bana shakti hai jo ek hi process ka ander alag-alag kaam karte hai, lekin agr unme sa koi ek thread ksi blocking operation ma ruk jaye to kai situations ma pura process ruk shakta hai qoki operating system ko individual user-level threads ka actual knowledge nahi hota.
  - **2) Kernel-level Thread (KLT)** : Kernel-level Thread ek aisa thread hota hai jisko os ka kernel direclty create, manage, schedule, pause aur resume karta hai, isiliye os har thread ko independently samajh shakta hai aur multiple CPU cores par ek hi process ka alg-alag threads ko sach ma parallel chala shakta hai, jissa multitasking aur multicore performance better hoti hai, lekin kernel involement hone ki wajah sa in threads ko create aur manage karna user-level threads se thoda heavier aur costly hota hai.
  - **3) Hybrid Thread** : Hybrid Thread model ek aisa system hota hai jisme user-level threads aur kernel level threads dono ke features ko combine kiya jata hai taki application fast thread management ka benifit bhi le sake aur os ke real parallel execution ka advantage bhi use kar sake, isiliye application ka ander bahut sare user-level threads chal shakte hai aur operating system unko kuch kernel-level threads ka through CPU par execute karwata hai, jissa performance aur flexibility dono improve karne ki koshish ki jati hai. 

---

### Thread Models
Thread models ya btata hai ki user-level threads aur kernel level threads ek dusre sa kaisa map hote hai. Mtlb Application kitna threads banati ha aur OS kernel unko kaisa handle karta hai. 
1. **Many-to-One** – Bahut sare user-level threads ko sirf ek kernel-level thread ka through chalaya jata hai.  
2. **One-to-One** – Har ek user-level ka exactly ek kernel-level thread hota hai.  
3. **Many-to-Many** – Bahut sare user-level threads ko limited number ka kernel-level threads ka uper map kiya jata hai.
