## Process State

Process state is the current condition of a process that shows what the process is doing at a given time, such as using the CPU, waiting, or being ready to run.

There are **5 standard process states** in a core operating system.

### i) New
New is the state where a process has just been created but has not started execution yet.  
At this stage, the user or OS sends a request to create a process, the OS creates a **Process Control Block (PCB)**, assigns a unique **Process ID (PID)**, and estimates basic resource requirements.  
The process is not using the CPU because it has not yet entered the Ready queue.

### ii) Ready
Ready is the state where a process is fully prepared to execute but is waiting for the CPU to become available.  
In this state, the process has program code, required memory, and necessary resources, but the CPU is busy.  
So, the process is placed in the **Ready Queue**.

### iii) Running
Running is the state where a process is actually executing on the CPU.  
The CPU is executing instructions, the process is doing its work, and registers and the program counter are actively changing.  
In a single-core CPU, only one process can be in the Running state at a time, while in a multi-core CPU, one process can run on each core.

### iv) Waiting / Blocked
Waiting or Blocked is the state where a process temporarily stops using the CPU because it is waiting for an I/O operation or some external event.  
In this state, the process does not use the CPU.  
After the waiting condition is over, the process is moved back to the Ready state.

### v) Terminated / Exit
Terminated is the state where a process has finished execution or has been forcefully stopped by the OS.  
In this stage, the OS frees the process memory, closes open files, and removes the PCB.  
This is the final state, and once a process enters this state, it cannot move to any other state.

## Process State Transition

Process state transition means the movement of a process from one state to another due to an event or an OS decision.

### i) New → Ready
This transition happens when the OS successfully creates the process and allocates memory and basic resources.  
A process cannot directly go to the Running state; it must first enter the Ready state.

### ii) Ready → Running
This transition occurs when the CPU becomes free and the scheduler selects the process.  
From the Ready queue, only one process can move to the Running state at a time in a single-core CPU.

### iii) Running → Waiting (Blocked)
This transition happens when a process makes an I/O request or waits for an event and must release the CPU.  
In the Waiting state, the process is not eligible for CPU execution.

### iv) Waiting → Ready
This transition occurs when the I/O operation is completed or the required event happens.  
The process then moves back to the Ready queue and waits for CPU allocation again.

### v) Running → Ready
This transition happens when the time slice expires or a higher-priority process arrives, which is called **pre-emption**.  
The OS temporarily stops the current process and gives the CPU to another process.

### vi) Running → Terminated
This transition occurs when the process completes successfully, an error occurs, or the user/OS kills the process.  
After this transition, the OS releases all resources and deletes the PCB.

---

## Why Process States Are Needed

Process states are needed so that the OS can use the CPU efficiently, manage multiple processes, perform fair scheduling, avoid CPU waste during I/O wait time, and make multitasking possible.
