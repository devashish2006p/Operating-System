## Inter Process Communication (IPC)

Inter Process Communication (IPC) is an OS mechanism through which different processes share data, exchange signals, and coordinate without breaking memory isolation. IPC allows processes to communicate safely and in a controlled way.

---

### Modes of IPC
There are **two modes** of IPC:

#### 1. Message Passing Mode
This mode lets processes send and receive data in the form of **messages**. The communication goes through the **kernel**, which temporarily stores the message and delivers it safely to the receiver.

**Mechanism:**
1. **Communication Channel Created** – OS creates a message channel inside the kernel.  
2. **Sender Sends Message** –  
   - Process A prepares the message (data + metadata).  
   - System call (send/write/msgsnd) is made. Control goes from user mode → kernel mode.  
3. **Kernel Receives Message** – Copies message to kernel buffer, checks permissions, adds it to message queue.  
4. **Receiver Waits/Ready** – Process B either waits for the message or it stays in the queue.  
5. **Receiver Reads Message** – Process B calls receive/read/msgrcv. Kernel copies message from buffer to receiver.  
6. **Receiver Resumes** – Kernel moves receiver from Ready → Running. Receiver processes message. Message passing complete.

**Sub-Modes:**
1. **Synchronous Message Passing** – Sender waits until receiver is ready. Both must meet at the same time.  
2. **Asynchronous Message Passing** – Sender sends message once; kernel stores in queue. Receiver can read later. Sender and receiver independent.

---

#### 2. Shared Memory Mode
This mode lets two or more processes access the **same memory region** to directly read/write data without involving the kernel each time.

**Mechanism:**
1. **Shared Memory Segment Created** – Process requests shared memory; kernel allocates a physical memory block with a unique ID.  
2. **Memory Mapping** – Maps the shared memory into virtual address space of processes. Virtual addresses may differ but physical memory is same.  
3. **Permissions & Protection Set** – Kernel sets Read/Write/Execute permissions; unauthorized processes blocked.  
4. **Direct Access** – Processes read/write directly using pointers. Fastest IPC method.  
5. **Synchronization Needed** – Semaphores/Mutex/Spinlocks used to protect critical section.  
6. **Data Visibility Ensured** – CPU cache & memory ordering managed; memory barriers ensure updated data.  
7. **Detach & Cleanup** – Kernel frees memory after work completion.

> Shared memory mode does not have sub-modes like message passing.

---

### Types of IPC

#### i) Pipes
A temporary, kernel-managed communication channel that allows **one-way (half-duplex)** data transfer between related processes.

**Flow:**  
`Process A (write) -> Kernel pipe buffer -> Process B (read)`

**Nature:**
- Direction: One-way  
- Scope: Parent-child  
- Persistence: Temporary  
- Kernel Role: Buffer & synchronization  
- Speed: Moderate  

**Types of Pipe:**
1. **Unnamed/Anonymous Pipe** – Temporary, used for related processes; destroyed when processes terminate.  
2. **Named Pipe / FIFO** – Persistent, exists in filesystem, allows communication between related or unrelated processes.

**Mechanism:**
1. Pipe created in OS.  
2. Process writes to kernel buffer.  
3. Another process reads from buffer.  
4. Blocking occurs if buffer full/empty.  
5. Pipe closed/destroyed after termination.

---

#### ii) Message Queues
Kernel-managed queue where processes send/receive **messages** stored until read.

**Features:**
- Message-based, fixed size  
- Asynchronous, sender & receiver need not be active simultaneously  
- Kernel stores messages until read  
- FIFO / priority order  

**Mechanism:**
1. Queue created by OS, given unique ID/name.  
2. Sender sends message (data + type/priority); kernel stores it in queue.  
3. Receiver receives message; kernel copies to receiver buffer, removes from queue.  
4. Synchronization automatic, race conditions avoided.  
5. Queue destroyed when deleted or system shutdown.

**Message Queue vs Pipe/FIFO:**

| Aspect             | Pipe / FIFO         | Message Queue            |
|-------------------|------------------|------------------------|
| Data type          | Byte stream       | Structured messages     |
| Coupling           | Tight             | Loose                   |
| Storage            | Temporary buffer  | Persistent until read   |
| Multiple senders   | Limited           | Yes                     |
| Priority           | No                | Yes                     |

---

#### iii) Shared Memory
Memory area accessible by multiple processes **simultaneously**.

**Mechanism:**
1. Process requests shared memory; kernel reserves block, gives unique ID.  
2. Process attaches memory to its virtual space.  
3. Another process attaches using same key.  
4. Read/Write occurs directly; no kernel copy.  
5. Synchronization required manually.  
6. Detach & destroy memory when done.

---

#### iv) Semaphores
Control mechanism to manage how many processes/threads use a shared resource.

**Core Idea:** "Take permission → use resource → release permission"

**Components:**
1. Integer value – available resource count  
2. Wait (P/down) – Blocks process if resource not available; decreases value  
3. Signal (V/up) – Releases resource; increases value, wakes waiting process  

**Mechanism:**
1. Process wants resource  
2. Calls `wait()`  
3. Enters critical section if allowed  
4. Works  
5. Calls `signal()`  
6. Resource freed  

**Types:**
1. **Binary Semaphore** – Value 0 or 1; allows one process at a time  
2. **Counting Semaphore** – Integer ≥0; allows multiple identical resources access

---

#### v) Signals
Lightweight notification to a process about an **event**.  
Used for: terminate, pause/resume, error notify, child status, interrupts. Does **not carry data**.

---

#### vi) Sockets
Kernel internal communication object for IPC.

**Components:**
1. IP Address – identifies machine  
2. Port Number – identifies process/service on machine  
3. Protocol – communication rules  

---

### Blocking and Non-Blocking IPC

- **Blocking IPC** – Process waits if data not ready; CPU idle.  
- **Non-Blocking IPC** – IPC call returns immediately; process continues work; data may be given or error/status returned.
