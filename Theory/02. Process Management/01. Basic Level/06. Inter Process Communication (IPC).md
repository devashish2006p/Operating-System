## Inter Process Communication (IPC)

Inter Process Communication (IPC) ek OS mechanism hai jiske through different processes data share karte hain, signals exchange karte hain, aur coordinate karte hain bina memory isolation ko todhe. IPC processes ko safe aur controlled way me communicate karne allow karta hai.

---

### Modes of IPC
IPC ke **do modes** hote hain:

#### 1. Message Passing Mode
Is mode me processes **messages** ke form me data send aur receive karte hain. Communication **kernel** ke through hota hai, jo message ko temporary store karke safely receiver tak pahunchata hai.

**Mechanism:**
1. **Communication Channel Created** – OS kernel ke andar ek message channel create karta hai.  
2. **Sender Sends Message** –  
   - Process A message prepare karta hai (data + metadata).  
   - System call (send/write/msgsnd) hoti hai. Control user mode → kernel mode me jata hai.  
3. **Kernel Receives Message** – Message ko kernel buffer me copy karta hai, permissions check karta hai, aur message queue me add karta hai.  
4. **Receiver Waits/Ready** – Process B ya to wait karta hai ya message queue me pada rehta hai.  
5. **Receiver Reads Message** – Process B receive/read/msgrcv call karta hai. Kernel message ko buffer se receiver tak copy karta hai.  
6. **Receiver Resumes** – Kernel receiver ko Ready → Running state me lata hai. Receiver message process karta hai. Message passing complete.

**Sub-Modes:**
1. **Synchronous Message Passing** – Sender tab tak wait karta hai jab tak receiver ready na ho. Dono ko ek hi time par milna padta hai.  
2. **Asynchronous Message Passing** – Sender ek baar message bhej deta hai; kernel usse queue me store kar leta hai. Receiver baad me read kar sakta hai. Dono independent hote hain.

---

#### 2. Shared Memory Mode
Is mode me do ya zyada processes ek hi **memory region** ko access karte hain aur directly read/write karte hain bina har baar kernel involve kiye.

**Mechanism:**
1. **Shared Memory Segment Created** – Process shared memory request karta hai; kernel ek physical memory block allocate karta hai unique ID ke saath.  
2. **Memory Mapping** – Shared memory ko processes ke virtual address space me map kiya jata hai. Virtual address alag ho sakte hain par physical memory same hoti hai.  
3. **Permissions & Protection Set** – Kernel Read/Write/Execute permissions set karta hai; unauthorized processes block hote hain.  
4. **Direct Access** – Processes pointers use karke directly read/write karte hain. Yeh fastest IPC method hai.  
5. **Synchronization Needed** – Semaphores/Mutex/Spinlocks ka use hota hai critical section protect karne ke liye.  
6. **Data Visibility Ensured** – CPU cache aur memory ordering manage hoti hai; memory barriers updated data ensure karte hain.  
7. **Detach & Cleanup** – Kaam khatam hone ke baad kernel memory free karta hai.

> Shared memory mode me message passing jaisa koi sub-mode nahi hota.

### Types of IPC

#### i) Pipes
Pipe ek kernel-managed half-duplex (one-way) IPC mechanism hai jo related (ya FIFO ke case me unrelated) processes ke beech byte stream ke roop me data transfer karne ke liye use hota hai. Pipe me internally hone wale lagbhag saare operations—pipe create karna, data buffer karna, data transfer karna, synchronization aur cleanup—kernel hi perform aur manage karta hai. Normal Pipe Half Duplex communication type support karta hai. Ishme sirf related processes he support karte hai mtlb related processes ka beech he communication possible hai. 

- **Internal Mechanism**
   1. Pipe Creation – Process pipe() system call karta hai; control kernel mode me jata hai aur kernel RAM me ek pipe object aur fixed-size circular buffer create karta hai.
   2. Read & Write End Create – Kernel do file descriptors return karta hai: fd[0] (read end) aur fd[1] (write end), jo isi pipe object ko point karte hain.
   3. Process Sharing – fork() ke baad parent aur child dono ko ye file descriptors inherit ho jate hain, isliye dono same pipe ke through communicate kar sakte hain.
   4. Unused End Close – Parent aur child apne kaam ke hisaab se unnecessary read ya write end close() kar dete hain, taaki communication direction clear rahe.
   5. Data Write – Sender write() call karta hai; kernel user-space buffer se data copy karke pipe ke kernel buffer me FIFO order me store karta hai.
   6. Buffer Management – Kernel read pointer aur write pointer maintain karta hai, jisse data jis order me aaya hai usi order me store aur retrieve hota hai.
   7. Data Read – Receiver read() call karta hai; kernel pipe buffer se data copy karke receiver ke user-space buffer me de deta hai.
   8. Synchronization – Kernel automatically reader aur writer ko synchronize karta hai, isliye dono processes ko manually buffer manage nahi karna padta.
   9. Blocking Behavior – Agar buffer empty ho to reader wait karta hai; agar buffer full ho to writer wait karta hai (blocking mode me).
   10. EOF Detection – Jab sabhi write ends close ho jate hain aur buffer khali ho jata hai, to read() 0 return karta hai, jo End-of-File (EOF) indicate karta hai.
   11. Resource Cleanup – Jab read aur write dono ends close ho jate hain aur koi process pipe use nahi kar raha hota, kernel pipe buffer aur uske resources automatically free kar deta hai.
- **Memory/Data Flow**
   1. Sender process apni user-space memory me data banata hai.
   2. write() call hoti hai aur control kernel mode me chala jata hai.
   3. Kernel data ko user-space → kernel pipe buffer me copy karta hai.
   4. Pipe buffer data ko FIFO (First In, First Out) order me temporarily store karta hai.
   5. Receiver read() call karta hai.
   6. Kernel data ko kernel pipe buffer → receiver ke user-space memory me copy karta hai.
   7. Receiver process us data ko use karta hai.

- **Blocking and Non-Blocking Behavior**
   - Blocking Behavior : Agar pipe buffer empty ho aur process read() kare, ya buffer full ho aur process write() kare, to kernel us process ko wait (block/sleep) state me rakh deta hai jab tak operation complete na ho jaye.
   - Non-Blocking Behavior : Agar pipe non-blocking mode (O_NONBLOCK) me ho, to read() ya write() wait nahi karte; operation turant return ho jata hai. Agar data available na ho ya buffer full ho, to error (EAGAIN/EWOULDBLOCK) return hoti hai.

- **Synchronous Vs Asynchronous**
  - Pipe ko officially "Synchronous IPC ya Asynchronous IPC" nahi bola jata hai. Ya behavior blocking ya non-blocking mode par depend karta hai.
    - Blocking pipe → Synchronous behavior jaisa act karta hai (sender/receiver ko wait karna pad sakta hai).
    - Non-blocking pipe → Asynchronous behavior jaisa act karta hai (wait nahi karta, turant return karta hai).
- **Advantages**
   - Simple – Implement aur use karna bahut easy hai.
   - Fast – Same machine par kernel buffer ke through efficient communication deta hai.
   - Automatic Synchronization – Kernel reader aur writer ko automatically manage karta hai.
   - Low Overhead – Chhote data exchange ke liye lightweight IPC mechanism hai.
- **Limitations**
   1. Unnamed Pipe sirf related processes ke beech kaam karta hai.
   2. Half-Duplex – Ek time par sirf ek direction me data transfer hota hai.
   3. Temporary – Process terminate hone ya descriptors close hone par pipe khatam ho jata hai.
   4. Limited Buffer Size – Kernel buffer fixed size ka hota hai; full hone par writer block ho sakta hai.
   5. Same System Only – Network ke across communication nahi kar sakta.
- **Security & Permissions**
   - Unnamed Pipe ko sirf valid file descriptors wale related processes access kar sakte hain, jabki Named Pipe (FIFO) par Linux file permissions (owner/group/others) aur kernel access control apply hota hai, isliye sirf authorized processes hi uske through communicate kar sakte hain.

#### ii) Message Queues
Kernel-managed queue jaha processes **messages** send/receive karte hain jo tab tak store rehte hain jab tak read na ho jaye.

**Features:**
- Message-based, fixed size  
- Asynchronous, sender aur receiver ek hi time par active hona zaroori nahi  
- Kernel messages ko tab tak store karta hai jab tak read na ho  
- FIFO / priority order  

**Mechanism:**
1. Queue OS dwara create hoti hai, unique ID/name milta hai.  
2. Sender message bhejta hai (data + type/priority); kernel usse queue me store karta hai.  
3. Receiver message receive karta hai; kernel usse receiver buffer me copy karta hai aur queue se hata deta hai.  
4. Synchronization automatic hoti hai, race conditions avoid hote hain.  
5. Queue delete hone ya system shutdown par destroy ho jati hai.

**Message Queue vs Pipe/FIFO:**

| Aspect             | Pipe / FIFO         | Message Queue            |
|-------------------|------------------|------------------------|
| Data type          | Byte stream       | Structured messages     |
| Coupling           | Tight             | Loose                   |
| Storage            | Temporary buffer  | Persistent until read   |
| Multiple senders   | Limited           | Yes                     |
| Priority           | No                | Yes                     |

---

#### iii) Shared Memory
Ek memory area jo multiple processes dwara **simultaneously** access kiya ja sakta hai.

**Mechanism:**
1. Process shared memory request karta hai; kernel block reserve karta hai aur unique ID deta hai.  
2. Process memory ko apne virtual space me attach karta hai.  
3. Dusra process same key se attach karta hai.  
4. Read/Write directly hota hai; koi kernel copy nahi hoti.  
5. Synchronization manually karna padta hai.  
6. Kaam ke baad memory detach aur destroy ki jati hai.

---

#### iv) Semaphores
Control mechanism jo manage karta hai ki kitne processes/threads ek shared resource ko use kar sakte hain.

**Core Idea:** "Permission lo → resource use karo → permission release karo"

**Components:**
1. Integer value – available resources ka count  
2. Wait (P/down) – Agar resource available nahi hai to process block ho jata hai; value decrease hoti hai  
3. Signal (V/up) – Resource release karta hai; value increase hoti hai aur waiting process ko wake karta hai  

**Mechanism:**
1. Process ko resource chahiye  
2. `wait()` call karta hai  
3. Agar allowed ho to critical section me enter karta hai  
4. Kaam karta hai  
5. `signal()` call karta hai  
6. Resource free ho jata hai  

**Types:**
1. **Binary Semaphore** – Value 0 ya 1 hoti hai; ek time par sirf ek process allowed  
2. **Counting Semaphore** – Integer ≥0 hota hai; multiple identical resources allow karta hai

---

#### v) Signals
Lightweight notification jo process ko kisi **event** ke bare me batata hai.  
Use hota hai: terminate, pause/resume, error notify, child status, interrupts ke liye. Data carry nahi karta.

---

#### vi) Sockets
Kernel internal communication object jo IPC ke liye use hota hai.

**Components:**
1. IP Address – machine ko identify karta hai  
2. Port Number – machine ke andar process/service ko identify karta hai  
3. Protocol – communication ke rules define karta hai  

---

### Blocking and Non-Blocking IPC

- **Blocking IPC** – Process wait karta hai agar data ready nahi hai; CPU idle rehta hai.  
- **Non-Blocking IPC** – IPC call turant return kar deta hai; process apna kaam continue karta hai; data ya to milta hai ya error/status return hota hai.
