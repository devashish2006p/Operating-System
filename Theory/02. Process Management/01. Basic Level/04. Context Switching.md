## Context Switching

**Definition:**  
Context Switching is the process in which the CPU stops executing one process and starts executing another. During this, the OS saves the execution context of the first process and restores the context of the next process.

---

### When Context Switching Happens
1. **Time Slice Expire** – Scheduler decides “switch to next process.”  
2. **Process Waits for I/O** – Disk, keyboard, or network wait.  
3. **Higher Priority Process Arrives** – Preemption occurs.  
4. **System Call or Interrupt** – CPU control is transferred to OS to handle events.

---

### Mechanism of Context Switching
1. **Interrupt / Scheduler Decision** – Timer or event triggers scheduler to select next process.  
2. **Current Process Context Save** – OS saves CPU registers, program counter, stack pointer, and updates process state in PCB of the current process.  
3. **Next Process Selection** – Scheduler selects process from ready queue based on priority or scheduling policy.  
4. **Next Process Context Restore** – OS loads CPU registers, stack pointer, and program counter from PCB of the next process.  
5. **CPU Execution Resume** – CPU starts executing the next process exactly from where it left off.

---

### Types of Context Switching

#### 1. Process Context Switching
- Occurs when CPU switches from one **process** to another.  
- OS saves and restores the **entire process context**, including memory management info, open files, and CPU registers.  
- Heavier and slower compared to thread context switching.

#### 2. Thread Context Switching
- Occurs when CPU switches between **threads of the same process**.  
- Only **thread-specific context** (CPU registers, stack pointer, program counter) is saved/restored.  
- Memory space, page tables, and open files remain the same.  
- Faster and lightweight compared to process context switching.
