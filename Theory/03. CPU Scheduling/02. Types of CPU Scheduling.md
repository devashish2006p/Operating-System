# Types of CPU Scheduling

## 1) Pre-emptive Scheduling

Pre-emptive scheduling is a scheduling technique in which the operating system has full control over the CPU. The OS can **forcefully take the CPU from a currently running process** and give it to another process, even if the first process has not completed its execution.

### Core Mechanism

i) Multiple processes are present in the ready queue. Each process has its own priority, remaining CPU time, and state.  

ii) A **timer interrupt** continuously runs. The CPU contains a hardware timer that generates interrupts at fixed intervals, which forces the OS to make scheduling decisions.  

iii) When an interrupt occurs, a **context switch** is triggered.  

iv) The scheduler decides whether the current process should continue or whether:
- a higher priority process has arrived
- a shorter job has arrived
- the time slice has expired  

v) If required, the CPU is taken away from the running process. The current process moves from **Running → Ready**, and the new process moves from **Ready → Running**.  
This act is called **pre-emption**.

---

### Algorithms of Pre-emptive Scheduling

#### i) Round Robin Scheduling

In Round Robin scheduling, the CPU is assigned to processes in the ready queue in a circular order. Each process gets the CPU for a fixed **time quantum**, and when the time expires, the OS forcefully takes the CPU and gives it to the next process.

##### How It Works

1) All processes enter the ready queue.  
2) The scheduler assigns the CPU to the first process.  
3) Time quantum (for example, 10ms) completes → pre-emption occurs.  
4) If the process is incomplete, it moves to the end of the queue.  
5) The next process runs, and the cycle repeats.

---

#### ii) Pre-emptive Priority Scheduling

In this algorithm, each process is assigned a priority. If a **higher priority process** enters the ready state, the OS immediately pre-empts the currently running lower priority process.

##### How It Works

1) Multiple processes exist in the system with fixed or dynamic priorities.  
2) The scheduler checks the ready queue based on priority.  
3) A process is running on the CPU.  
4) If a higher priority process arrives, the OS performs an interrupt and context switch.  
   - Current process → Ready state  
   - High priority process → Running state  

---

#### iii) Shortest Remaining Time First (SRTF)

SRTF is a pre-emptive scheduling algorithm in which the CPU is always assigned to the process with the **shortest remaining execution time**. If a new process arrives with a shorter remaining time, the OS pre-empts the current process.

##### How It Works

1) Multiple processes are present in the ready queue.  
2) The remaining CPU burst time of each process is checked.  
3) The process with the minimum remaining time gets the CPU.  
4) If a new process arrives with a shorter remaining time than the running process, the OS performs a context switch and assigns the CPU to the new process.

---

#### iv) Multilevel Queue Scheduling

In this scheduling technique, processes are permanently divided into different queues based on their nature. Each queue has its own scheduling algorithm, and **higher priority queues can pre-empt lower priority queues**.

##### How It Works

1) A new process arrives.  
2) The OS identifies the process type or class.  
3) The process is assigned to a fixed queue.  
4) The scheduler always checks the highest priority queue first.  
   - If a higher queue has ready processes, lower queues do not get the CPU.  
   - If the higher queue is empty, the next queue gets the CPU.

---

#### v) Multilevel Feedback Queue Scheduling (MLFQ)

MLFQ is an advanced pre-emptive scheduling algorithm in which process priority is **not fixed**. The priority changes dynamically based on process behavior, such as CPU usage and I/O behavior.

##### How It Works

1) **Process Creation** – A new process always enters the highest priority queue.  
2) **Execution** – The scheduler selects the highest non-empty queue.  
3) **Feedback Decision** –  
   - If the process uses its entire time quantum, it is demoted to a lower queue.  
   - If the process blocks early for I/O, it remains in the same queue or gets promoted.  
4) **Pre-emption** – If a higher priority process arrives, the lower queue process is immediately pre-empted.  
5) **Aging** – If a process waits for a long time, the OS gradually increases its priority.

---

## 2) Non Pre-emptive Scheduling

Non pre-emptive scheduling is a CPU scheduling mechanism in which **once a process gets the CPU, the OS does not take it back forcefully**. Context switching happens only in two cases:
1) The process terminates  
2) The process moves to I/O wait  

---

### Core Algorithms of Non Pre-emptive Scheduling

#### i) First Come First Serve (FCFS)

In FCFS scheduling, the process that arrives first in the ready queue gets the CPU first. Once assigned, the OS does not interrupt the process until it finishes or blocks.

##### How It Works

1) A process enters the ready queue.  
2) The queue follows arrival time order.  
3) The CPU is assigned to the first process.  
4) The process runs until completion.  
5) The CPU becomes free.  
6) The next process gets the CPU.

---

#### ii) Non Pre-emptive Shortest Job First (SJF)

In this algorithm, the process with the shortest CPU burst time is selected first. Once assigned the CPU, the process runs until completion or I/O wait. The OS does not take the CPU back even if a shorter job arrives.

##### How It Works

1) Multiple processes are present in the ready queue.  
2) The scheduler compares CPU burst times.  
3) The process with the shortest burst time is selected.  
4) The CPU is assigned to that process.  
5) The process completes or goes to I/O wait.  
6) After CPU becomes free, the next shortest job is selected.

---

#### iii) Non Pre-emptive Priority Scheduling

In this scheduling method, the process with the highest priority in the ready queue gets the CPU. Once assigned, the process runs until it completes or blocks.

##### How It Works

1) Multiple processes are present in the ready queue.  
2) The scheduler checks the priority of all processes.  
3) The highest priority process is selected.  
4) The CPU is assigned to that process.  
5) The process terminates or moves to I/O wait.  
6) After CPU becomes free, the next highest priority process is selected.
