## 7) HRRN (Highest Response Ratio Next)

HRRN is a **non-preemptive CPU scheduling algorithm** in which the decision to assign CPU to a process is based on its **Response Ratio**.  
The response ratio considers **both waiting time and burst time**, which means a process that has waited longer and has a shorter execution time gets higher priority.

### Mechanism

i) Identify all processes present in the ready queue.  
ii) Calculate the waiting time for each process.  
iii) Calculate the Response Ratio (RR) using the formula.  
iv) Assign the CPU to the process having the **highest response ratio**.  
v) After process completion, update the ready queue.  
vi) Repeat steps 2 to 5 until all processes are finished.

## 8) CFS (Completely Fair Scheduler)

Ya ek CPU scheduling algorithm hai jo Linux Kernel ma use hota hai jo CPU ko sabhi processes ka beech fair tarike sa distribute karta hai jisme har process ko ushke "virtual runtime" ka basis par equal chance deta hai. 

### 8.1 Working Mechanism 
1. Jab system start hota hai, har CPU apna ek runqueue banata hai jisme sab runnable processes store hote hain.
2. Har process ko ek value di jati hai jise vruntime kehte hain jo uska CPU usage track karti hai.
3. Sab processes ko ek sorted structure (Red-Black Tree) me rakha jata hai jahan ordering vruntime ke basis par hoti hai.
4. Scheduler jab bhi run hota hai, wo tree ka leftmost (minimum vruntime) process select karta hai.
5. Selected process ko CPU par run karne diya jata hai.
6. Jab process run karta hai, uska vruntime continuously increase hota rehta hai.
7. Vrunt ime ka increase process ki priority (nice value) ke hisaab se fast ya slow hota hai.
8. Har thode interval (timer interrupt) par scheduler check karta hai ki kya koi aur process ka vruntime current se kam hai.
9. Agar kisi dusre process ka vruntime kam milta hai, to current process ko preempt karke naya process run kar diya jata hai.
10. Agar koi process I/O ya sleep me chala jata hai, to uska vruntime ruk jata hai aur wo runqueue se temporarily remove ho jata hai.
11. Jab wo process wapas aata hai, to uska vruntime relatively kam hota hai, isliye usko jaldi CPU mil jata hai.
12. Jab naya process system me aata hai, to uska vruntime current minimum ke around set kiya jata hai taaki fairness bani rahe.
13. Scheduler continuously runqueue ko update karta rehta hai (insert, delete, reorder) taaki vruntime sorting correct rahe.
14. Yeh pura process baar-baar repeat hota hai jab tak system chal raha hota hai.

### 8.2 Virtual Runtime (vruntime)

Virtual runtime is a **counter** that tracks how much CPU time a process has consumed relative to its fair share.  
CFS always selects the process with the **lowest vruntime**.

## 9) Real-Time Scheduling

Real-time scheduling is a CPU scheduling technique in which the OS **guarantees that critical processes receive CPU within a fixed time limit**, making execution predictable.  
Here, **when a task executes is more important than fairness**.

### Mechanism

i) Each real-time task has defined attributes:
- Execution Time – how long CPU is required  
- Deadline – by when the task must complete  
- Period – how often the task repeats  
- Priority – how critical the task is  

ii) When a task becomes ready, it is placed into a **real-time ready queue**, which is separate from the normal queue.  
iii) The scheduler checks priority or closest deadline to select the task.  
iv) The selected real-time task immediately gets CPU, and if a normal process is running, it is pre-empted.  
v) The task runs continuously without interference until execution completes or its time slice ends.  
vi) After completion, the task exits or waits for the next activation if it is periodic.

---

## 10) Deadline Scheduling

Deadline scheduling is a **real-time CPU scheduling technique** in which the scheduler always assigns the CPU to the process whose **deadline is closest**, ensuring no critical task misses its time limit.

### Mechanism

i) Task parameters are defined.  
ii) The ready queue is ordered based on deadlines.  
iii) The scheduler selects the task with the **earliest deadline**.  
iv) If a new task arrives with an earlier deadline, the current task is immediately pre-empted.  
v) The task runs until completion or until it is pre-empted by a more urgent task.

---

## 11) Batch Scheduling

Batch scheduling groups similar jobs into a **batch** and executes them sequentially without user interaction.  
Here, **throughput is more important than response time**, and it is mostly non-preemptive.

### Mechanism

i) Job Submission – Users submit programs, which are stored on disk in a batch queue.  
ii) Job Selection – The OS selects jobs using algorithms like FCFS, SJF, or HRRN.  
iii) Execution – The job is loaded into memory and runs until completion.  
iv) Termination – After completion, output is stored and the next job starts.

---

## 12) Idle Scheduling

Idle scheduling occurs when the system has **no runnable processes**.  
The scheduler assigns the CPU to a special **idle task** to keep the CPU in a safe state and handle power management.

This is **not a real scheduling algorithm**, but a **fallback mechanism** to avoid CPU waste and support power saving.

### Mechanism

i) The ready queue is empty.  
ii) The scheduler selects the idle task (one idle thread per CPU, lowest priority).  
iii) The CPU enters an idle state and executes the `hlt` (halt) instruction, entering low-power sleep mode.  
iv) The CPU waits for an interrupt.  
v) As soon as an interrupt arrives and a runnable task appears, the idle task stops and normal scheduling resumes.

---

## 13) Proportional Share Scheduling

In proportional share scheduling, each process receives CPU time **in proportion to its assigned weight or share**.  
Processes with higher importance get more CPU time.

### Mechanism

i) Each process is assigned a share or weight based on priority or importance.  
ii) Total shares of all runnable processes are calculated.  
iii) CPU allocation is decided proportionally.  
iv) Processes execute while the scheduler continuously monitors CPU usage.  
v) If a process exceeds its fair share, its execution is delayed and under-served processes are preferred.

---

## 14) Lottery Scheduling

Lottery scheduling is a **proportional share, pre-emptive scheduling technique** in which each process is given lottery tickets.  
On each scheduling decision, a random ticket is drawn and the corresponding process gets the CPU.

### Mechanism

i) Ticket Assignment – Each process receives tickets based on CPU share or priority.  
ii) Random Draw – The scheduler randomly selects a ticket number.  
iii) CPU Allocation – The process holding the selected ticket gets the CPU.  
iv) Repeat – A new lottery is held at every scheduling event.

---

## 15) Stride Scheduling

Stride scheduling is a **deterministic version of lottery scheduling**.  
Each process has a fixed stride value.  
More tickets mean a **smaller stride**, resulting in more frequent CPU access.  
This is a pre-emptive scheduling algorithm.

### Mechanism

i) Stride value is calculated for each process.  
ii) Pass value is initialized (initially pass = 0).  
iii) The scheduler selects the process with the **minimum pass value**.  
iv) After execution, the pass value is updated:  
   `pass = pass + stride`  
v) The process with the next minimum pass value is selected again.
